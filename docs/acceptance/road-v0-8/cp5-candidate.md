## 离线保存报错与连续保存修复

- 用户离线输入并保存后报告 `validation_failed`。重连前读到云恢复列表为空，镜像重连后仍可见新增正文，
  因此先将两页完整原文另存于 `offline-failure/visible-unsaved-raw.json` 及 Markdown 副本，未自动重试保存。
- 联网后 Mac 实际收到“离线手机合成修改”，该文件的更新时间为 `2026-09-07T11:00:07.179507-04:00`。
  读回副本 `offline-failure/cloud-after-reconnect.md` 的 SHA-256 为
  `f99486517ec6f7e6f1e0ea2cf2c7412121577f1bfb70bd0cbd8ead30eb939540`。
  这说明正文曾成功保存并同步；不能把随后报错解释为该次内容一定未提交。
- 定向复现确认：成功保存后，前端清空当前原文快照，紧接着再次保存会跳过恢复记录写入，
  宿主因缺少该记录返回 `validation_failed`。修复保留当前快照，让后续保存先持久化恢复记录；
  开始新操作时也清除旧成功提示，避免错误旁仍显示先前“已保存”。没有放宽宿主校验或自动重发写入。
- 回归覆盖不改正文再次保存、继续编辑后保存，以及恢复写入失败时保留输入并清除旧成功提示。
  完整前端 `141 passed`，最后定向 `8 passed`；Mac 与实体 iPhone 新候选普通界面连续两次保存均成功。
- 两端已重建、签名、解包校验；手机已安装 `save-fix/` 候选。旧候选及原始失败文件保留。
  用户确认新版离线复测正常，新增韩文测试字段成功保存。Mac 重连读回副本包含该字段，
  更新时间为 `2026-09-07T11:19:42.874248-04:00`；副本 `save-fix/offline-retest-readback.md`

## 回退与问题记录

- 候选使用独立标识，不替换正式桌面 app；停止候选进程可返回原 app。
  不删除候选 Vault、恢复 journal 或云冲突文件，不把旧二进制指向新私有 journal。
- 云端变化按导出的原字节副本及当前磁盘状态人工核对；不自动选赢者、合并、改 code 或重发未知写入。
- 已知工程上限：原生文件批次和单份私有 journal 串行处理，大量稿件或 provider 延迟时可能影响响应时间；
  尚无性能测量，不把它改成额外后台服务。本阶段未据此新增产品范围。
- 未解决 P0／P1 或任一必需项无证据时，停在候选待验。全部必需项通过并取得开发者接受之后，才完成 CP5。
  Road 快照、tag、push 和发布另行处理。
