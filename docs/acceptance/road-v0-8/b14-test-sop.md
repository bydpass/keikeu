# Road v0.8 CP5：B14 测试 SOP

日期：2026-09-07。状态：流程已编写，**尚未执行，不构成 B14 通过证据**。
对应 [候选验收单 B14](cp5-candidate.md)。目标：真实账号／容器不可用及 Drive 关闭期间，错误可识别，本机恢复仍可取回、导出；恢复服务后只读核对，不自动覆盖或重发旧保存。

## 1. 开始条件

- 使用独立 Apple 测试设备／账号及合成数据；Mac、iPhone 分别记录结果。当前没有独立测试设备／账号，先停在准备阶段，不在日常设备退出账号或关闭 Drive。
- 安装已核验的同源码候选，记录源码、包摘要、平台和系统版本。当前产品源码为 `83c4f60`，候选身份 `app.keikeu.v08candidate`，容器 `iCloud.app.keikeu.v08probe`。换设备若需要重新签名，先验证包身份和容器权限，不能沿用旧安装回执。
- 另一台测试设备保持在线作为核对端。所有试验只操作专用容器中的新合成稿，不选择真实作者 Vault。
- 执行人手动操作系统账号设置；每次只改变一项。记录原设置，确认能登录回原测试账号。不修改开发者门户、签名权限或云端容器，也不卸载应用、清除应用数据。
- 系统界面名称以执行设备为准；若没有下述单项控制，记录“无法触发”，不要用更大范围设置变更代替。

## 2. 每个场景前建立基线

1. 保持在线，选择候选 iCloud 存储。创建专用合成 Paper，第一页写 `B14 baseline 中文 English`，第二页写 `B14 page 2 한국어`，保存；在另一端打开，逐页核对一致。
2. 在测试端追加 `B14 retained draft`，不保存为正式 Paper。通过“导出草稿”导出到本机文件位置；从私有恢复记录读回，确认该修订、两页正文及元数据完整。提示“草稿保留”本身不能代替读回。
3. 准备一份已经完整保全的合成冲突副本，导出原字节并核对摘要。使用既有合成恢复副本即可，不必再制造冲突。
4. 由协助者备份候选私有恢复记录、存储选择及合成云文件到独立本机目录，建立文件大小／SHA-256 清单。确认备份可读后再改变系统设置。敏感账号标识、私有路径和原始记录留在忽略目录，验收文档只记脱敏结论。

## 3. 分别触发三个场景

每行独立执行，并完整执行第 4、5 节后才进入下一行。Mac、iPhone 的结果分别填写，不能互相替代。

| 场景 | 人工触发动作 | 必须记录的实际证据 |
| --- | --- | --- |
| B14-A：账号不可用 | 仅在独立测试设备退出原 Apple 测试账号；保留候选应用及其本机数据 | 返回候选刷新后，原生账号能力是否确实不可用；界面完整错误码。源码对应 `icloud_account_unavailable`，不能只凭系统退出动作判通过 |
| B14-C：容器不可用 | 在系统提供候选应用的单独 iCloud 使用开关时，关闭该应用的访问，保持账号登录及全局 Drive 开启 | 必须观察候选原生容器查询实际不可用；源码对应 `icloud_container_unavailable`。若只是停止同步、容器仍可达，或没有独立开关，本场景记“未触发”，不能算通过 |

## 4. 故障期间检查

1. 回到候选，刷新 Library。记录完整错误码、发生操作和时间；不能静默切到另一 Vault，也不能显示云保存成功。
2. 检查“本机恢复草稿”：打开第 2 节的草稿，逐页核对正文、标题及 Tags。点击保存一次，确认失败后输入仍完整；保留回执，先不要反复保存。
3. 从恢复列表“导出”草稿到本机非 iCloud 目录；先取消一次，确认草稿保持，再完成一次。协助者解析导出 JSON，对比保存前后的草稿字段；有效 Paper 的导出不能代替原文草稿导出。
4. 从“冲突与恢复版本”点击既有副本的“导出原字节”，完成本机导出。文件必须与基线副本逐字节一致；此时不要点击“检查并保全全部冲突版本”或“恢复为活动稿”，它们需要访问云端。
5. 确认最新草稿已在私有恢复区读回后，正常关闭并重开候选，保持故障条件。再次打开恢复草稿及导出副本，核对内容、修订和摘要。没有读回确认前不要终止应用。
6. 保持测试端不保存，在另一在线测试端给正式合成稿追加 `B14 remote newer` 并保存。保留该版本副本及摘要，供恢复后的旧草稿覆盖保护检查。

## 5. 恢复原设置并核对

1. 恢复刚才关闭的开关，或重新登录原测试账号。先让系统完成连接；回到候选刷新，先不保存、不恢复为活动稿。
2. 协助者确认实际云账号／容器及当前存储选择。重新登录后若系统返回不同身份或候选报 `icloud_account_changed`，先导出旧本机恢复，按显式存储连接流程处理；不能改写私有账号键来强行连接，也不能把身份未恢复算通过。
3. 只读检查第 4 节的远端新版本仍在，摘要与副本一致；旧草稿、冲突副本仍完整。若界面显示结果未知，使用其只读核对入口，确认状态后再操作。
4. 确认未发生自动保存或重发后，显式对旧草稿保存一次：应拒绝覆盖已变化的远端稿并保留双方。记录真实返回码；再次核对远端文件、草稿与恢复副本。
5. 新建另一份合成稿并显式保存，从另一端读回验证服务恢复。保留所有基线、导出及回执，恢复测试前存储选择；本 SOP 不执行数据清理。
