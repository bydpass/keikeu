## 本轮实现

- 两端共用 Rust 存储路由。本地 Mac 保留 Python；iPhone 本地与双端 iCloud 使用共享 Rust Core。
  `host.*` 不进入 Python；转交 Python 前剥离宿主作用域，原 JSONL protocol v2 不变。
- 设备私有区持久化存储身份、语言及选择。先检查目标、确认离开，再原子保存选择并增加 generation；
  失败保留原工作面。请求及异步结果校验作用域；Python 在途请求和未决保存／恢复阻止切换。
  Python 请求守卫在正常结束和任务取消时释放。
- 只有显式选择 iCloud 才初始化专用工作区；不搬入本机稿件。Apple 原生接口发现账号、容器及 metadata，
  呈现尚未下载、可读、上传中等状态；下载是显式请求，上传状态不代表另一设备已收到。
  读取与写入使用原生文件协调批次；Core 只读本次登记的文件，发现新增未登记文件时拒绝写入并要求重新发现。
  固定容器／目录身份、无符号链接访问、临时发布、CAS 与回滚继续成立。
- 私有恢复不依赖 provider 可用性。云端账号或目录不可用时仍列出原文草稿和保全副本，可导出。
  正式写入后的账号检查失败返回未知结果；不重发写入。
- 原生冲突版本和 provider 改名 sibling 均先保全原字节及摘要；整批原子落盘并读回校验后，才标记原生版本已解决。
  Native 版本 token 绑定账号及工作区，仅作当前进程句柄；sibling 文件保持原样。
- 明确恢复有效副本前再次检查活动稿摘要，先保全活动稿（包括损坏原字节），再持久化恢复意图并使用共享 CAS 发布器。
  损坏副本只允许导出。已保全且经明确恢复确认的 sibling 以路径及原字节摘要核对；变化后重新阻断写入。
  未知恢复只读核对为已提交、未提交或内容已变化，不自动重试；副本始终保留。
- 沿用私有 journal 版本 1，通过缺省字段兼容 CP3 恢复记录；未知字段仍拒绝静默吞掉。
  未新增依赖、账号、后台服务、遥测或自建同步层。

## 真实 iCloud 在线往返

使用现有候选身份及已授权容器，专用 `CP4-<UUID>` 合成目录；未选择或迁移真实作者 Vault。
Mac 候选使用现有 cloud entitlement，不新增 App Sandbox 限制；iPhone 使用现有开发 profile。
`Info.plist` 声明已有容器，未更改开发者门户或设备账号。

显式 debug 参数启用同一 Router/Core/Apple 文件适配器；普通编辑工作面被阻断，不触发 Python Vault 启动流程。
release 不含该入口。每次回执使用独立文件，失败记录不覆盖。

1. Mac 保存两页合成 Paper，只读核对保存已提交，Unicode `STRASSE` 搜索成功；回执通过。
2. iPhone 首次更新未通过：发现云文件但尚未下载。初版测试入口把该状态归为通用校验错误，后已细分原因。
3. iPhone metadata 回执确认 `not_downloaded`，通过 `host.cloud.download` 请求下载；随后重启测试入口，
   读入 Mac 稿、修改第二页、保存并只读核对、搜索成功；更新回执通过。
