## 2. 已确定的产品决定

- 最低 iOS **18.0**，支持目标 **iOS 18–27**；不为 iOS 15–17 增加兼容代码或验收任务。历史 Demo 配置保留原样。
- 移动端使用原生语言和组件，尽可能保留 Rust 内核。Mac 后续重构，Windows 保留当前代码结构。
- 参考体验采用“**快速调出＋查看**”；点击输入区后系统收起参考是允许行为。返回输入时不得丢失正文、光标、选区或未完成的组合输入。
- 融合方案为首选：岛内渲染最多3行、预留4行显示区；系统卡片从当前位置起显示同页最多3段。实际字体与可用面积必须重新测量，不能把 Demo 的字宽估算当作产品布局。
- 整份参考在主应用选择和切换；外部入口只读、翻段、关闭，不加入搜索、编辑或每次翻段确认。
- 自动分段在未溢出的最后一个合适标点处切开；没有合适标点时按可容纳的完整字符边界切开。手动切点仅在“进一步”模式；有一段超出限制便整组拒绝应用，指出段号及原因，显示回退自动分段并保留待修正切点。
- 操作按钮覆盖必须主动 opt-in。安装、首次启动、普通打开均不提示或建议启用；用户主动进入“入口设置”后才提供影响、配置和恢复说明。进入设置不等于授权更改绑定。
- 旧 B14 已关闭，不重新挂为待办；新原生版本对实际存在的账号／容器／Drive 失败路径另行定义证据，不预先宣称问题消失。
- 2026-09-30 用户决定：新 iPhone 版改为 Swift 原生，**沿用旧身份 `app.keikeu.v08candidate`**；旧 Tauri iPhone 版退役，不再作为验收对象，其 iOS 入口（`lib.rs` 的 `cfg(target_os = "ios")` 部分与 `tauri.ios.conf.json`）随步骤2抽离移除。iCloud 容器**保留 `iCloud.app.keikeu.v08probe`**，不改名、不迁移 Mac 库。含 iCloud 能力的显式 App ID 与签名 profile 在步骤1核对；wildcard profile 只用于不含 iCloud 的合成测试包。
- 2026-09-30 用户决定：融合参考可与原生编辑器并行开工，顺序见第 6 节。

## 3. 首版使用流程

### 快速记录并可靠放下

主应用提供直接可达的“新 Paper”，进入正文即可输入；Paper 名、页标题和 Tags 不成为开写门槛。保存验证整份 Paper，保留现有标题／正文非空和最多一个总结页的规则。加页、删页及光标拆分保持 [SPEC](SPEC.md) §4–5 的内容语义，原生布局可调整。

明确区分“未保存”“本机草稿已保护”“Paper 已保存”和“保存结果待核对”。私有草稿落盘不冒充正式保存；保存期间继续输入时，旧响应不能覆盖新文字或清除较新草稿。离开、切稿、切库和进入后台时保全当前可持久化修订；强制结束只承诺恢复最后成功落盘的修订。

### 选好参考，快速查看

从列表或已保存 Paper 主动选为参考，确认使用的页面与版本；未保存输入先保留，由用户决定保存后作为参考，不能把私有草稿静默投到系统界面。应用内可读完整内容；按设备能力启动岛内参考或调用系统卡片。读者在两种入口翻段，回到原编辑器继续输入。更换整份 Paper、刷新源文、整理切点及结束参考均在主应用处理。

Spotlight 只作系统发现入口，不记为“编辑器内直观唤起”已经解决。跨应用验收至少覆盖一个用户主动选择、实际可用的入口；操作按钮不是使用原生编辑器或应用内参考的前提。

### 自愿整理，再使用

基本模式可以直接写、保存和参考。“进一步”模式提供现有页类型及参考切点预览；作者可按光标添加或移除切点，预览合格后应用。无效切点不修改 Paper，不逐段追问确认，也不阻止普通保存。首版先完成这些整理能力，不引入独立卡片库、学习调度或派生文件链。

### 找回草稿与失败后的内容

恢复入口能显示最后落盘修订、所在存储及可执行动作：恢复、导出、明确丢弃。格式损坏、冲突、源件不可下载或写入结果未知时，先保全并显示真实状态，再允许核对或恢复；不能通过重复点击保存绕过阻塞。

导航候选为“写作／资料列表／参考”，存储、语言、恢复和入口设置从明确的次级入口进入。步骤1以可点击原型固定布局、返回路径与异常状态；本计划不把页面数量或控件样式提前固定成架构。

## 4. 实现边界与待验证契约

以下为计划采用的最小实现方向；步骤1用源码审查与合成往返验证后冻结。验证不成立时记录具体原因再调整，不提前搭建替代框架。

| 责任 | 复用入口与实施约束 |
| --- | --- |
| Paper 规则 | [keikeu-core](../crates/keikeu-core/src/lib.rs) 保持纯规则；编解码、校验、编号和 NFC＋Unicode casefold 共用，不另写 Swift 解析器 |
| 保存与恢复 | 从 [store.rs](../apps/desktop/src-tauri/src/paper/store.rs)、[host/mod.rs](../apps/desktop/src-tauri/src/host/mod.rs)、[private.rs](../apps/desktop/src-tauri/src/host/private.rs)、[conflicts.rs](../apps/desktop/src-tauri/src/host/conflicts.rs) 抽出实际共用部分，放入不依赖 Tauri 的新宿主 crate（名称步骤1定），`keikeu-desktop` 改为依赖它；Mac iCloud 路径与新 iOS 调用同一实现，不复制成长期分叉。Mac 本地库仍走 Python，不在本次抽离范围 |
| 路由与系统能力 | [router.rs](../apps/desktop/src-tauri/src/host/router.rs) 保留存储身份、代次及失败语义；[platforms/apple](../platforms/apple/) 拥有文件协调、下载和系统分享；Tauri/Python 桌面分流留在桌面适配层 |
| Swift–Rust 桥接 | 现有代码只有 Rust→Swift（`keikeu_host_native`、`keikeu_coordinate`），须新增 Swift→Rust 导出，仍用 C ABI＋JSON。iOS 上 `platforms/apple` 的 Swift 宿主源码只由 App target 编译一次，Rust 侧只留 `extern` 声明；Mac 的 `build.rs` 编译方式不变。每个导出函数以 `catch_unwind` 包住并把 panic 映射为结构化错误；Rust 分配的返回缓冲只由 Rust 导出的释放函数释放。固定长度、错误、串行写入、取消与句柄生命周期。新增桥接依赖只有在具体缺口成立且获批准后采用 |
| 调用线程 | Swift 对 Rust 的调用全部在同一非主线程串行执行器上进行，主线程不直接调用（`Cloud.discover` 与导出面板会同步等待主队列，否则死锁）。`discover` 与导出一样移到宿主锁外执行，草稿写入不得排在最长 15 秒的文件发现之后 |
| 原生编辑 | SwiftUI 管导航与可见状态；原生文本控件按中文组合输入、光标／选区、撤销和长文滚动选择。必要时用 UIKit 文本控件，不自制文本引擎 |
| 参考呈现 | 应用拥有持久阅读状态；岛、卡片和应用内视图读取同一参考会话。复用 Demo 的已证实行为，替换合成正文、固定字宽和进程内位置。分段在 App 进程内完成；岛只经活动状态接收当前一段文字，首版不设 App Group。App 取不到岛的实际宽度，排版按保守宽度测量、岛内限定动态字号上限、保留“渲染行数小于显示行数”的余量，并按设备类别×横竖屏×字号取证 |

系统分享面板不能占用草稿写入队列。现有 [Host.swift](../platforms/apple/Host.swift) 会等待面板结束，新 Swift 入口不能在主线程直接调用该阻塞路径。取消界面任务不等于撤销已开始的文件替换；结果丢失进入只读核对，不能自动重放写入。

### 参考状态与私密边界

1. 参考会话绑定存储身份、Paper、页面、源内容摘要及分段版本。页无独立持久身份时使用“该修订内的页序号”，不擅自向 Paper 写入新 ID。
2. 自动分段为只读投影，段内容连接后须精确还原对应原文；保留空白、换行、emoji、组合字符及字面“｜”。不为适应窗口自动改写或丢弃作者文字。
3. 手动切点与阅读位置为本机辅助状态，与私有写作草稿分开，不写入 Paper v4，不冒充跨设备同步数据。切点绑定源修订；源文变化后不静默套用旧偏移，保留旧切点供核对。
4. 源文变化时由用户明确刷新参考；已缓存版本必须标示。若源件消失或不可下载，仅在缓存有效且允许展示时保留旧参考，否则回到应用处理，不静默跳到另一份内容。
5. 位置应可在进程重启、活动结束、无岛环境和快速交替翻段后恢复。翻段请求绑定会话及修订，旧请求不能影响新选参考；持久化失败时不得谎报位置已保存。岛与卡片的翻段意图都在 App 进程执行（Demo 设备日志已见），位置存于 App 容器内的小文件，原子替换并带会话与修订，旧修订请求直接拒绝；只有确需跨进程访问时才增加共享容器及对应权限。步骤1验证活动结束或进程被杀后的恢复。
6. 参考只在用户主动发起后呈现，不上传正文。默认先收紧：活动的锁屏呈现不显示正文，只显示“参考进行中”与页段号；调出卡片的意图设 `authenticationPolicy = .requiresAuthentication`，锁屏时须先解锁；锁屏状态下岛内是否可见正文列为步骤1必核对项，不可隔离则锁屏时不在岛内放正文。放宽任一默认须有实机证据并由用户决定。App 切换器快照同样实机核对。
7. 结束参考时停止本应用创建的活动，撤销可继续显示的参考会话，清理可重建正文缓存；保留作者文件和恢复草稿。重启后不自动再次向系统界面投射正文。系统仍可能保留的快照边界如实说明，不承诺无法验证的彻底擦除。

## 5. 支持目标与证据分级

支持范围为 iOS 18–27 中实际存在的版本。产品宿主和扩展以18.0为部署下限，按 API 与硬件能力启用入口；下表是交付目标，不是已通过的兼容清单。

| 环境 | 必须可用 | 额外入口与检查 |
| --- | --- | --- |
| iOS 18 等未提供本方案 Snippet API 的系统 | 原生创作、保存恢复、应用内参考 | 带岛且权限允许时提供互动速览；无岛也能独立完成创作与参考 |
| iOS 26–27，带岛机型 | 上述能力 | 系统卡片与岛共用位置；分别验证冷热启动、双向切换、正文布局和返回输入 |
| iOS 26–27，无岛机型 | 原生创作、应用内参考、系统卡片 | 卡片不能依赖活动存在或进程内默认位置 |
| 活动权限关闭、入口未配置或系统暂不可用 | 原生创作与应用内参考 | 明确原因和返回路径，不循环唤起，不催促用户覆盖操作按钮 |

步骤1核对已安装 SDK、实际可用系统与签名能力，冻结设备矩阵。最低版本、Snippet 首个支持版本和当前高版本分别记录工程、模拟器、实机证据；代表性带岛／无岛设备、中文键盘及动态字号按受影响能力覆盖。旧模拟器结果仅作 legacy；新增模拟器检查也不能替代真机的系统入口、输入法或 iCloud 观察。

无可用设备的项目记为“未验”，允许继续不依赖它的工程，但不写成“支持已验证”。最终若必须缩减验收覆盖或调整支持承诺，由用户明确决定；不得因缺设备自行放宽判据。

### 步骤1：固定流程与技术契约

**工作与产物：**制作快速记录、选参考、进一步整理及恢复的可点击流程原型，包含空、忙、错误和返回状态；形成 Swift／Rust 方法与字段、线程／内存、参考状态、隐私、测试包身份和旧数据接续契约。以合成 Paper 完成 Swift→Rust→Swift 最小往返；核对所有拟用 API 的系统门槛和签名权限。确定新原生源文件归属，构建物继续进入忽略的测试目录。

**通过条件：**合法与非法请求、结构化错误、Unicode 字符、反复创建／释放、取消后结果处理均有可运行检查；最小 iOS 产品壳可构建并链接 Rust；草稿写入不受系统面板阻塞的调度方案明确；参考位置持久化及扩展访问边界有最小验证。三条主流程可评审，锁屏隐私、测试隔离和旧恢复数据保全不存在悬空决定；阻断所选方案的缺口未解决时本步不能通过。桥接未成立前不铺设完整界面。

产物清单（逐项给出证据形式）：① 可点击原型；② 契约文档，含新宿主 crate 边界、Swift 宿主单次编译、导出／释放／panic 规则、调用线程与锁外执行；③ 桥接往返检查，至少跑通一个宿主方法（如 `paper.create_draft` → `host.draft.put` → 重启读回），另含注入 panic 不崩溃、结果标为未知；④ 位置持久化与恢复检查，用经 Rust 读出的合成 Paper 而非静态文本；⑤ 锁屏与 App 切换器实机核对记录；⑥ `app.keikeu.v08candidate` 与 `iCloud.app.keikeu.v08probe` 的显式 App ID／profile 核对及旧数据访问边界清单；⑦ 设备矩阵。

### 步骤2：打通保存与恢复

**工作与产物：**抽出原生客户端确需的共享运行逻辑，接入本地 Apple 目录；保留现有 Mac 调用入口。提供新建草稿、打开、保存、只读核对、草稿落盘／读回、损坏原件导出和基础检索的原生调用链。
