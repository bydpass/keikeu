失败、修复与边界

  • 新工作区缺少测试临时父目录、旧归档引用、共享旧 venv 的打包来源问题均已定位并修复；最终 sidecar 来自独立环境与新源码。
  • CP1 凭据钩子误报旧测试占位值，缩短该合成值后定向复测并提交；未关闭钩子。
  • 首次 Mac 临时签名开启 Hardened Runtime，内部 Python 库签名不匹配导致 sidecar 启动失败。只调整忽略的调试 overlay 为 ad-hoc、Hardened Runtime 关闭后重新构建并完成全部冒烟；正式签名配置未改，不能用此结果宣称可公证分发。
  • 界面工具的批量输入／剪贴板竞态在保存前逐字段校正，最终磁盘无无关剪贴板内容；这不证明真实输入法候选场景通过。
  • B10 同编号新建的实测为 provider 改名副本；原生冲突由旧 B09／B11 证明，不能合并为未实际发生的组合。B14 账号／容器不可用条件不足，转交 v09.01，不能降格为已通过。
