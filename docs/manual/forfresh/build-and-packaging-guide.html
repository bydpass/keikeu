构建与打包

把“装 Python 项目”“生成 Sidecar”“构建前端”“编译 Rust”和“制作可分发应用” 分开看，再沿今天的源码走完一条真实构建链。

keikeu contributors 简体中文 2026-08-29 Node 22.23.2 contract Python >=3.11,<3.14

先分清三个结果

editable install 让源码可被 Python 导入，Sidecar build 把 Python 链做成一个本机可执行文件， Tauri build 才把前端、Rust 宿主和 Sidecar 组合为桌面应用。

  1. npm run build 只生成前端静态资产，不会生成完整桌面应用。
  2. scripts/build_sidecar.py 只重建 Sidecar，不会签名、公证或证明产品流程。
  3. 日常开发、Road v0.9 打包演练和 Developer ID 候选是三个不同 Gate，证据不能混用。
事实边界：本页是 2026-08-29 的非权威教学快照，不修改或批准发布合同。 当前可运行链仍仅是桌面版本。构建事实最终核对当前 manifest、lockfile 与脚本； 跨端基础核对 Road v0.8 计划，发布阶段核对 PROJECT 与未来获批的 Road v0.9 计划，权限与证据核对 RULES。

Chapter 01

六层工具，各管一段

同一条命令链里出现 Python、Node 和 Rust，不代表它们在做同一件事。

层 当前工具 输入 输出或作用 不负责
Python 开发安装 pip install -e pyproject.toml 与 src/ 让虚拟环境从当前源码导入 keikeu_core、keikeu_bridge 独立可执行文件、桌面 bundle
Python build backend Hatchling 项目 metadata 与 package 映射 按 Python 打包标准向 pip 提供 editable/wheel 构建能力 PyInstaller onefile、Tauri 应用
Python 冻结 PyInstaller 6.21.0 sidecar_entry.py 与 Python 模块 目标平台的单文件 Sidecar 前端、Rust 宿主、签名
前端构建 Vite 8.1.5 Vue、CSS 与静态资源 frontend/dist/ Rust binary、Sidecar、产品验收
原生编译 Cargo / Rust 1.88 Rust host、Tauri crates、Cargo lock 当前 target 的原生宿主 Python 冻结、Apple 公证
桌面组合 Tauri CLI / bundler Vite 资产、Rust host、Sidecar、bundle 配置 开发应用或配置指定的 bundle 自动授予 Developer ID 信任

editable install 为什么仍然需要 backend

python -m pip install -e ".[dev]" 不复制一份长期脱离源码的 keikeu。 pip 读取 pyproject.toml， 按 Hatchling 的 package 映射把 src/keikeu_core 与 src/keikeu_bridge 暴露给虚拟环境。修改源码后通常无需重新安装； metadata、依赖或 package 映射改变时再装一次。

Hatchling 是 build backend，不是应用运行时依赖。项目当前只在 [build-system] 声明 hatchling，没有在运行时依赖里添加它； 本页不为后续 Road 擅自发明一个精确版本锁。

Chapter 02

Python 到 Sidecar

Tauri 不直接运行仓库里的 Python 文件；它启动一个按 target triple 命名的冻结可执行文件。 

scripts/sidecar_entry.py
  import keikeu_bridge.sidecar.main
            │
            ▼
scripts/build_sidecar.py
  rustc -Vv → host target triple
  python -m PyInstaller --onefile
            │
            ▼
frontend/src-tauri/binaries/
  keikeu-sidecar-aarch64-apple-darwin
            │
            ▼
tauri.conf.json externalBin: binaries/keikeu-sidecar
            │
            ▼
Rust shell().sidecar("keikeu-sidecar") → protocol v2 hello
  1. sidecar_entry.py 保持入口极薄，只调用现有 JSONL stdin/stdout service。
  2. build_sidecar.py 从 rustc -Vv 读取 host，而不是手写后缀。
  3. PyInstaller 以 --onefile 冻结入口，并通过 --paths src 找到项目包。
  4. 最终 binary 写到 frontend/src-tauri/binaries/；中间 work、spec 与 cache 写到 build/pyinstaller/。
  5. tauri.conf.json 使用无 target 后缀的 externalBin 基名，Tauri 选择当前目标对应文件。
  6. Rust 宿主通过 Tauri shell plugin 启动 keikeu-sidecar，再以 protocol v2 system.hello 核对会话。
不要直接附着 Sidecar

Sidecar 的生命周期、stdin/stdout 和重启语义由 Rust/Tauri 持有。日常调试可观察 ./dev 管理的宿主日志；不要另开一条人工通道窥探或抢占内部进程。

Chapter 03

Vite、Cargo 与 Tauri

Tauri 是编排入口：开发时连接 Vite，构建时先产出静态前端，再让 Cargo 编译宿主并组合 bundle。

开发启动

npm --prefix frontend run tauri:dev
  1. Tauri CLI 读取 frontend/src-tauri/tauri.conf.json。
  2. beforeDevCommand 运行 npm run dev，Vite 提供 http://127.0.0.1:1420。
  3. Cargo 编译并启动 debug Rust host，WebView 载入 Vite 页面。
  4. 宿主从 externalBin 启动已存在的 Sidecar。

完整构建

npm --prefix frontend run tauri:build

beforeBuildCommand 运行 npm run build，Vite 把 Vue 前端写入 frontend/dist/。Cargo 随后编译 release host；Tauri 将 frontendDist、host 与 external binary 组合成当前配置要求的 bundle。 今天 bundle.targets 只列 app；Road v0.9 的获批发布 Gate 才负责明确 DMG target 与 rehearsal 配置。

证据不要越级

Vite build 只证明前端能产出；Cargo build 只证明 Rust 能编译；Tauri build 只证明 当前配置能组合产物。它们都不自动证明签名、公证、普通安装、重启、文件交接或产品接受。

Chapter 04

./dev 的两条路

TUI 没有另一套 build system；它只用固定 argv 包装两条已有命令。

键 实际动作 何时使用 失败边界
a npm --prefix frontend run tauri:dev Sidecar 已存在，且 Python 部分未改变 缺少固定 Sidecar 时停止并提示使用 b
b 先运行 .venv/bin/python scripts/build_sidecar.py；成功后再启动应用 Python core/bridge 或冻结输入改变后 build 非零退出时停在日志页，不静默启动旧 binary

./dev 自身由系统 python3 >=3.11 运行，但冻结步骤明确使用项目 .venv/bin/python。它只管理自己启动的进程组，日志只保存在内存；它不会 修改 Tauri 的 Sidecar 生命周期，也不会杀死占用端口 1420 的未知进程。 键位与安全边界见开发者 TUI 极简使用手册。

Chapter 05

源码与产物边界

判断一个目录能否删除或提交，先问它是事实来源、安装环境、中间缓存，还是待审查的候选产物。

位置 性质 来源 Git / 证据边界
src/、frontend/src/、frontend/src-tauri/src/ 源码事实 人工维护 可进入聚焦提交；须审查 diff
.venv/、frontend/node_modules/ 本机安装环境 pip / npm ignored；不提交，不当产品证据
build/pyinstaller/ PyInstaller cache、work 与 spec 输出 build_sidecar.py ignored；可重建
frontend/src-tauri/binaries/keikeu-sidecar-* 目标平台 Sidecar binary PyInstaller ignored；必须由对应源码重建
frontend/dist/ 前端静态资产 Vite ignored；不替代源码
frontend/src-tauri/target/ Cargo binary 与 Tauri bundle 输出根 Cargo / Tauri ignored；release/bundle/ 下的 app/DMG 仍不是自动批准候选
local-first 仍然适用

构建不得读取真实 Vault 来“顺便测试”。smoke 使用隔离 Home 与 synthetic Vault； 应用 bundle、DMG、哈希、签名日志和作者资产都不进入普通源码提交。

Chapter 06

开发、演练与发布

输出都是 .app，也可能处在完全不同的信任状态；阶段名和实际证据必须一起看。

层级 目的 允许的动作 必须明确不声称
日常开发 快速联调当前源码 ./dev、Sidecar rebuild、tauri:dev、聚焦测试 可重复 release、签名、公证、用户验收
Road v0.9 packaging rehearsal 证明锁定工具链能从 clean checkpoint 生成不可分发 app/DMG 校准版本与 selector；显式 unsigned/ad-hoc 配置；检查 arm64、Info.plist、protocol hello；跑 synthetic smoke Developer ID 身份、Apple 接受、可外发候选
Developer ID candidate 生成可验证的签名、公证候选 仅在身份就绪且候选 Gate 单独授权后，从固定源码重新构建、签名、公证、staple 与哈希 沿用 rehearsal 产物或旧证据

rehearsal 不能调用真实签名私钥；若意外发现签名或公证环境输入，应停止演练。 Developer ID candidate 也不能复用 rehearsal 产物，必须从固定 source commit 全新构建。签名、公证、staple 与 Gatekeeper 的教学解释继续阅读Developer ID 发布手册； 实际进入条件仍以未来获批的 Road v0.9 计划为准。

Chapter 07

版本契约与 Road Gate

精确版本要从所有权文件读取；一张手册只能记录快照，不能替 manifest 和 lockfile 冻结环境。

工具 2026-08-29 仓库事实 事实来源 后续 Gate 待办
Node / npm 22.23.2 / 10.9.8 manifest contract；.node-version 仍为 22.23.1 frontend/package.json、.node-version 按获批 Road 值消除 selector 漂移
Python >=3.11,<3.14；.python-version 当前为 3.13.14 pyproject.toml、.python-version 核对 selector、实际稳定解释器与 build lock 注释
PyInstaller 6.21.0；lock 注明 macOS arm64 / Python 3.13.14 的旧解析上下文 requirements-build.lock 在稳定工具链重新解析和验证
Rust / Cargo 1.88.0、target aarch64-apple-darwin rust-toolchain.toml、Cargo.toml 核对实际稳定工具与 Cargo lock
Tauri Rust crate 2.11.5；CLI 2.11.4 Cargo.toml、package.json 与获批应用版本、bundle contract 和 build recipe 一起冻结

本次手册更新不修改 .node-version、.python-version、 rust-toolchain.toml、build lock 或 bundle 配置。现在修这些文件会提前进入 跨端基础或发布 Road 的实施范围，并让教学文档提交混入工具链决策。

新人最短检查路线

# 日常：使用开发 TUI
./dev

# TUI 外的同一条底层链
.venv/bin/python scripts/build_sidecar.py
npm --prefix frontend run tauri:dev

# Road v0.9 才使用的 packaging rehearsal 入口（须先满足获批 Gate）
npm --prefix frontend run tauri:build -- --bundles app,dmg

命令成功后仍要记录实际工具版本、运行日期、输出、未执行项和对应源码状态。 应运行哪些测试及每项证据能证明什么，见测试与证据手册； 各组件的职责与改动入口见技术栈与组件图鉴。
