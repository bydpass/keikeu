测试与证据手册

先问改动穿过哪一层，再跑能覆盖那一层的最小检查；每条结果只证明它真正观察到的事情。

keikeu contributors 简体中文 更新：2026-08-29 适用：Road v0.7 完成态

先记住这句话

绿色检查不是一张万能通行证。focused test、全套测试、构建、平台 smoke、开发者 QA 与产品验收，是六种不同结论。

  1. 从真实改动和 caller 选择测试，不按“顺手”选择命令。
  2. mock、jsdom、fake Home 与 synthetic Vault 都是隔离工具；隔离越强，能外推的真实环境结论越少。
  3. 报告实际命令、当次结果和没跑的检查；旧 pass count 不能续借。
事实边界：本页帮助理解当前测试链，不定义 Gate，也不授予真实 Vault、发布、签名或远程操作权限。最终证据规则看 RULES §8，当前阶段与实际结论看 PROJECT。

Chapter 01

先分清六种结论

证据强不强，不看命令跑了多久；看它是否真的经过了待证明的边界。

结论 需要看到什么 常见误报
Focused behavior 直接测试目标分支、输入、输出和失败路径。 一个测试通过，就说整个模块稳定。
Engineering complete 范围内源码、直接测试、相关回归、构建与风险记录均完成。 只看测试数量，不看漏掉的跨层边界。
Platform smoke 实际桌面链启动，并观察本机能力、Sidecar 生命周期与退出。 把 Vite build 或 Cargo test 叫作 Tauri smoke。
File-service smoke 在明确隔离的数据上实际完成目标文件流程并核对落盘结果。 synthetic Vault 成功，就声称真实 provider 可用。
Developer QA 开发者实际判断布局、键盘、文案、恢复路径和交互舒适度。 用 jsdom assertion 替代真实窗口判断。
Product accepted 按 SPEC 或 Planbook 的真实作者场景逐项完成，并由开发者作出接受判断。 把 build、测试或历史报告自动升级为当前验收。
最短判断

如果检查没有经过某个边界，它就不能证明那个边界。例如：jsdom 没启动系统 WebView；Cargo test 没启动打包后的 Sidecar；synthetic Vault 没经过作者的真实文件服务。

Chapter 02

改动与最小证据矩阵

先跑最接近改动的检查；只有改动跨层或风险升高时，才沿链向外扩。

改动类型 最小命令 Fixture / mock 证明什么 不能证明什么
Python core / bridge .venv/bin/python -m pytest -q tests/test_目标.py tmp_path、monkeypatch、synthetic Vault 被执行的模型、协议、service 或文件规则。 Vue、Rust、真实 Sidecar 或平台流程。
Python 公共行为或共享文件边界 .venv/bin/python -m pytest
.venv/bin/python -m compileall -q src		 testpaths 下的当前测试，排除 tests/test-vault 当前 Python 回归套件与源码可编译。 桌面 app 能启动或作者流程被接受。
单个 Vue 组件或 bridge helper npm --prefix frontend run test -- src/目标.test.js Vue Test Utils、jsdom、vi.mock bridge 组件状态、事件、DOM 语义和 IPC 参数。 真实 WebView、Rust command 或原生对话框。
Vue 共享行为或生产前端 npm --prefix frontend run test
npm --prefix frontend run build		 jsdom 测试；Vite 生产构建 当前前端回归与 Vite bundle 可生成。 Tauri 生命周期、Sidecar 或平台视觉 QA。
Rust host / command / worker cargo test --manifest-path frontend/src-tauri/Cargo.toml Rust fake child / spawner 与内存队列 测试覆盖的 policy、请求排序、timeout 与失败分类。 真实 Python binary、窗口或系统服务。
Sidecar 构建链 .venv/bin/python scripts/build_sidecar.py 不应读取 Vault 当前源码可生成目标 triple 的 Sidecar binary。 binary 可被 Tauri 启动、重启或安全退出。
完整桌面边界 ./dev 后按 b fresh fake Home、isolated TMPDIR、synthetic Vault 当次 Tauri / Rust / JSONL / Python 链的已观察路径。 未操作的 provider、真实作者数据或产品验收。
文档 .venv/bin/python scripts/check_docs.py
git diff --check		 无应用 fixture 活动文档、本地链接、预算、HTML id 与 diff whitespace。 任何应用代码、GUI、构建或产品行为。
Skill / context route .venv/bin/python -m pytest -q tests/test_build_context_pack.py
.venv/bin/python scripts/check_docs.py		 tracked synthetic paths；ignored output path 文件选择、冷上下文排除、二进制/逃逸/超限拒绝与输出 symlink 防护的被测规则。 当前生成包已经人工审查、应用行为正确或 checkpoint 被接受。
产品验收 无通用命令；执行当前 SPEC / Planbook 场景 明确获准的真实作者场景；先保留备份与边界记录 开发者实际接受的具体范围。 未执行场景、其他平台或未来版本。

文件名中的“目标”不是固定脚本：先用 rg 找改动 owner、caller 与直接测试，再把真实路径代入。若改动同时穿过 Vue、Rust 与 Python，三层测试都要跑；涉及桌面生命周期时再加 Tauri smoke。

Chapter 03

Python：pytest 与临时文件

pytest 负责执行 Python 行为；fixture 负责把输入和环境摆到可重复、可丢弃的位置。

tmp_path：每个测试自己的工作台

tmp_path 提供一个独立的 pathlib.Path。keikeu 用它创建 synthetic Vault、Index、Markdown 和备份目标，不需要碰作者目录。当前 pyproject.toml 还把 pytest 的 base temp 固定到 ignored 的 tests/test-vault/pytest，并明确排除该目录的递归收集。

monkeypatch：临时替换环境边界

monkeypatch 可在一个测试期间替换 Home resolver、系统调用或故障点，测试结束后恢复。它适合证明“写入失败后不改原 Vault”等分支；它不能证明真实操作系统恰好会以同样方式失败。

Focused 与 full suite

# 先跑直接测试
.venv/bin/python -m pytest -q tests/test_bridge_service.py

# 共享契约改变后再跑全部 Python 回归
.venv/bin/python -m pytest
.venv/bin/python -m compileall -q src

不要从历史文档复制旧 pass count。测试增删、选择器和环境都会改变结果；只有当前 working tree 上实际运行的输出才是当前证据。

Chapter 04

Vue：Vitest、Test Utils 与 jsdom

这三者一起提供快速组件证据，但它们各自不是浏览器、Tauri 或产品验收。

Vitest
发现和运行 *.test.js，提供 assertion、spy、mock 与异步测试控制。项目脚本是 npm --prefix frontend run test。
Vue Test Utils
用 mount 创建 Vue 组件 wrapper，并触发输入、点击、props 与 emits。它证明组件在测试环境中的可见状态和交互。
jsdom
vite.config.js 指定的模拟 DOM。它没有 macOS WebView 的渲染、窗口生命周期、原生 picker、IME 或真实尺寸感觉。
Bridge mock
vi.mock 替换 Tauri IPC helper，让组件可稳定测试成功、错误与 pending。它能钉住调用参数，不能证明 Rust 或 Python 收到请求。
# 单文件反馈
npm --prefix frontend run test -- src/PaperView.test.js

# 共享行为与生产前端
npm --prefix frontend run test
npm --prefix frontend run build
什么时候升级证据

改动触及 Tauri command、窗口关闭、原生能力、Sidecar 或布局舒适度时，Vitest 之后继续跑对应 Cargo test、真实 Tauri smoke 和规定尺寸的开发者 QA。

Chapter 05

Rust、构建与 Tauri smoke

Cargo test、Vite build 和 Tauri smoke 经过不同边界，三者不能互相代签。

Cargo test

当前 Rust tests 位于 frontend/src-tauri/src/bridge.rs，通过 fake child / spawner 检查单 worker、请求 envelope、timeout、kill 与 shutdown 等行为。命令从仓库根目录显式指定 manifest：

cargo test --manifest-path frontend/src-tauri/Cargo.toml

它会编译并执行 Rust test target，但不会自动证明真实 Sidecar binary、Tauri 窗口或系统 opener。

Vite build

npm --prefix frontend run build 证明 Vue 源码能进入生产前端 bundle。它不启动 Rust host，也不读取 externalBin。

Tauri smoke

完整启动前必须有当前源码构建的 Sidecar。首选从 ./dev 按 b，让工具先构建成功再启动；排障时可展开为：

.venv/bin/python scripts/build_sidecar.py
npm --prefix frontend run tauri:dev

smoke 记录实际观察的路径，例如启动、hello、选择 synthetic Vault、一次读写、退出和残留进程。没观察的动作必须写成“未运行”，不能从“窗口出现了”推断。

Chapter 06

隔离数据与证据记录

测试环境必须可丢弃，证据必须可复核；ignored 只防止误提交，不会自动保护真实数据。

四个安全工具

工具 用途 边界
tmp_path 单个 pytest 的文件树。 测试结束即可丢弃；不引用真实 Vault。
monkeypatch 临时 Home、系统调用和 fault injection。 只模拟指定边界；不能升级为平台证据。
fake Home 把 app config、local state 与默认路径隔离到 fresh 目录。 HOME / TMPDIR 只传给本次 app smoke；结果不代表真实 provider。若同一步还用 b 构建 Sidecar，应显式保留已批准的 RUSTUP_HOME / CARGO_HOME，或先构建再切 app Home，避免 fake Home 隐藏工具链。
synthetic Vault 用虚构内容练习读写、迁移、Trash 与恢复。 放在 ignored 的 tests/test-vault/；绝不拿唯一真实 Vault 做第一次实验。

一次证据记录至少写什么

  1. 状态：branch、HEAD、working tree，以及是否使用当前源码重建 Sidecar。
  2. 命令：完整记录实际执行的命令；不要只写“测试通过”。
  3. 结果：退出码、当次 pass/fail 和真正观察到的场景。
  4. 隔离：说明 fake Home、synthetic Vault、mock 或真实环境边界；去除作者正文、私有路径和 token。
  5. 遗漏：明确未跑的平台、provider、外部编辑器、视觉 QA 与产品验收。

四个禁止替代

  • 不拿旧 pass count 替代当前运行。
  • 不拿 build success 或 jsdom 测试替代 Tauri smoke。
  • 不拿 fake Home / synthetic Vault 替代真实作者验收。
  • 不拿 context pack 替代源码审查、测试、平台 smoke 或 checkpoint 接受。
真实 Vault 红线：迁移、删除、恢复和持久配置先在 fixture、copy 或 synthetic data 上验证。若验收确实需要真实作者场景，必须由当前 SPEC / Planbook 定义范围并获得开发者许可；测试便利不构成许可。
