给新人的
npm 手册

只学 keikeu 今天真正使用的 Node、npm 与前端命令：先核对版本，按锁文件安装， 再分清 Vite 页面和完整桌面应用。

keikeu contributors 2026-08-11 Node 22.23.2 npm 10.9.8

先记住三件事

在 keikeu 里，npm 只管理 frontend/ 的 JavaScript 依赖与脚本。 它不是 Python 后端，也不会替你完成 Rust、Sidecar 或产品验收。

  1. 从仓库根目录运行命令时，始终带上 --prefix frontend。
  2. package.json 写直接需求，lockfile 锁完整依赖树，node_modules 可以重建。
  3. 网页能打开只证明 Vite 在工作；完整桌面链路还需要 Tauri、Rust 和 Python Sidecar。

Chapter 01

npm 在项目里的位置

Node 运行前端工具，npm 安装这些工具并调用项目脚本；keikeu 的业务核心仍在 Python， 桌面宿主仍在 Rust/Tauri。

先把四层分开

  • Vue
    描述界面组件、状态与交互。
  • Vite / Vitest
    开发、构建和测试 Vue 代码。
  • Tauri / Rust
    提供桌面窗口、生命周期与本机能力。
  • Python Sidecar
    执行 Vault、Markdown、索引与业务规则。

npm 主要站在第二层，也负责调用本地安装的 Tauri CLI。它不会安装 Python 包， 不会运行 Cargo 测试，也不是一个常驻 Web 后端。

Chapter 02

五个文件与目录

只要能区分“需求、冻结结果、安装结果、构建结果”，就不会把依赖问题修成更大的依赖问题。

frontend/package.json
直接依赖、精确工具版本和脚本入口。private: true 防止误发布， type: module 表示前端 JavaScript 使用 ESM。
frontend/package-lock.json
npm 解析后的完整依赖树，当前格式为 lockfile v3。它必须进入 Git，团队与 CI 才能重建同一棵树。
frontend/node_modules/
本机安装结果，体积大、可重建、已被 Git 忽略。不要手改，也不要提交。
frontend/dist/
Vite 的构建输出，运行 npm run build 后生成，同样不进入 Git。
frontend/vite.config.js
当前开发服务器固定在 127.0.0.1:1420，并启用 strictPort； Vitest 使用 jsdom 环境。

一句话地图

package.json + package-lock.json
              │
              └── npm ci ──▶ node_modules/

Vue source ── npm run build ──▶ dist/
谁该进 Git

提交 package.json 与 package-lock.json；不提交 node_modules/ 或 dist/。删除 lockfile 不是“清缓存”，而是放弃当前冻结结果。

Chapter 03

第一次安装

先核对真正运行的版本，再用冻结安装；不要假设版本文件或包管理器会自动替你守好这道门。

第一步：从仓库根目录核对版本

node --version
npm --version

当前前端契约应输出：

v22.23.2
10.9.8

frontend/package.json 的 engines 同样写着这两个精确值， 但 engines 不一定是硬失败闸门；命令输出才是你此刻真正使用的工具。

已知漂移 · 不要藏起来

当前 frontend/package.json、lockfile、README 与 PROJECT 都写 Node 22.23.2，但仓库根目录 .node-version 仍是旧值 22.23.1；已完成的 Road v0.6 工具链记录也是 22.23.2。新人以当前 manifest 与 PROJECT 为准；校准该文件应当是独立、可审阅的任务， 不在安装时偷偷改。

第二步：按 lockfile 安装

npm --prefix frontend ci

npm ci 会：

  • 要求 package.json 与 lockfile 一致；
  • 先删除现有 frontend/node_modules/，再重建；
  • 按 lockfile 安装，不更新两个声明文件；
  • 首次安装或缓存未命中时访问 npm registry。

因此它适合新人、CI 和“把本机恢复到仓库声明状态”。不要给它加 sudo， 也不要为了消除报错先删 lockfile。

第三步：只读核对顶层依赖

npm --prefix frontend ls --depth=0

成功时应看到本手册第一章列出的直接依赖；缺包或版本不符时，先保留完整错误输出。

Chapter 04

日常命令

npm 脚本只是项目预先写好的短命令。先看它展开成什么，再判断它能证明什么。

从仓库根目录运行 实际脚本 结果
npm --prefix frontend run dev vite 启动本机 Vite 页面；进程持续运行，Control + C 停止。
npm --prefix frontend run test vitest run 单次运行全部前端测试，结束后退出。
npm --prefix frontend run test -- App.test.js vitest run App.test.js 把 -- 后面的文件名交给 Vitest，只跑相关测试。
npm --prefix frontend run build vite build 检查生产构建并写入 frontend/dist/。

拆开命令语法

npm  --prefix frontend  run  test  --  App.test.js
│          │             │     │    │        │
工具    npm 项目目录     跑脚本  脚本名 分隔符  交给 Vitest

npm run 会把本地 node_modules/.bin 加入 PATH，所以本项目不需要 全局安装 Vite、Vitest 或 Tauri CLI。脚本清单的唯一事实源是 frontend/package.json；仓库没有定义 npm start。

dev 不是完整应用

npm run dev 只监听 127.0.0.1:1420。端口已被占用时， strictPort 会让它失败，而不是偷偷换端口；先找出占用者，不要随手改配置。

Chapter 05

走到完整桌面应用

Tauri 开发命令会启动 Vite 和 Rust 宿主，但不会替你制造 Python Sidecar；缺一层就不是完整链路。

最短开发启动路径

  1. 安装前端依赖
    npm --prefix frontend ci
  2. 构建 Python Sidecar
    .venv/bin/python scripts/build_sidecar.py
  3. 启动桌面应用
    npm --prefix frontend run tauri:dev

第三步展开为 tauri dev。Tauri 读取 frontend/src-tauri/tauri.conf.json，先执行 npm run dev， 再让 Rust 宿主连接 http://127.0.0.1:1420，并启动已存在的 Sidecar 二进制。

为什么 Sidecar 必须先构建

Tauri 配置声明外部二进制 binaries/keikeu-sidecar；真正生成的文件名会带当前 Rust target triple。npm 既不安装 PyInstaller，也不运行 scripts/build_sidecar.py，所以缺 Sidecar 时应回到第二步，而不是重装 Vue 依赖。

生产构建入口

.venv/bin/python scripts/build_sidecar.py
npm --prefix frontend run tauri:build

tauri:build 会自动执行 Vite build，再调用 Cargo/Tauri 组装桌面产物。 它比 npm run build 多，但仍不自动证明签名、公证、真实 Vault smoke 或产品验收通过。

保护作者数据

启动真实桌面应用可能读取已选择的 Vault 与本地应用状态。测试迁移、删除、恢复或持久配置时， 先用 fixture、合成 Vault 或副本；npm 命令不会替你隔离真实作者内容。

Chapter 06

依赖变更纪律

新依赖不是修复手段，而是新的维护责任。先证明现有代码、平台能力和已安装包都不够，再增加。

默认：不要改依赖树

  • 不为“以后也许会用”安装包；
  • 不全局安装项目已经本地声明的 CLI；
  • 不运行 npm update 做顺手升级；
  • 不运行 npm audit fix 自动改树；
  • 不删除 lockfile 后重新解析“碰碰运气”。

本项目直接依赖全部使用精确版本。版本范围前的 ^ 或 ~ 会改变升级语义， 不应在无设计决定时顺手加入。

任务明确批准增加依赖时

# 运行时依赖
npm --prefix frontend install --save-exact <package>@<exact-version>

# 只用于构建或测试
npm --prefix frontend install --save-dev --save-exact <package>@<exact-version>
  1. 先说明为什么现有代码、浏览器/Tauri 原生能力和当前依赖不够。
  2. 确认它属于 dependencies 还是 devDependencies。
  3. 只审阅 frontend/package.json 与 lockfile 的预期差异。
  4. 重新运行前端测试与构建；跨桌面边界时再跑相应 Cargo/Tauri 检查。

安全报告不是自动改动授权

npm --prefix frontend audit --omit=dev 可以查询生产依赖报告，但它访问 registry， 结果只代表查询时刻。发现告警后先确认受影响路径和升级范围；不要把 npm audit fix 当成无害清理。

Chapter 07

故障与证据边界

先按错误属于哪一层分类。重装所有东西通常只会抹掉线索，并不能修复根因。

最短故障表

症状 最可能原因 下一步
找不到 package.json 在仓库根目录漏了 --prefix frontend 回到根目录，使用本手册中的完整命令。
EBADENGINE 或版本警告 实际 Node/npm 不符合 manifest；也可能被旧 .node-version 带到 22.23.1 先记录 node --version 与 npm --version，校准到 22.23.2 / 10.9.8。
npm ci 说 manifest 与 lock 不一致 声明文件真的发生了漂移 查看 Git diff；不要让 npm install 静默重写现场。
1420 端口占用 旧 Vite/Tauri 进程仍在运行 确认并停止占用者；不要绕开 strictPort。
浏览器页面能开，桌面调用失败 只运行了 Vite，没有 Tauri bridge 先构建 Sidecar，再运行 tauri:dev。
Tauri 报 Sidecar 不存在 Python 二进制尚未为当前 target 构建 运行 .venv/bin/python scripts/build_sidecar.py，保留原错误。

每条命令到底证明什么

检查 可以声称 不能顺带声称
npm run test 当前 Vitest 测试通过。 Python、Rust、真机或产品验收通过。
npm run build 当前 Vue/Vite 生产构建完成。 桌面包可以启动。
npm run tauri:dev 在实际观察到的路径上，开发宿主能够启动。 签名、公证、安装包或真实作者场景通过。
npm run tauri:build 当前本机桌面构建完成。 发布、兼容性或产品接受已经成立。

新人完成一次前端改动的最短检查

npm --prefix frontend run test
npm --prefix frontend run build
git diff --check

UI 行为变化还需要聚焦的 Vitest 与适当的 Tauri smoke；文档检查不能替代应用检查。 未运行的检查要明说。
