keikeu · macOS direct distribution

第一次理解 Developer ID 发布。

本页解释 Apple Developer Program、证书、签名、公证、staple 和 Gatekeeper 如何组成 Mac App Store 外的分发链路。它是教学材料，不是 当前可执行的打包计划。

Current state

已知什么，尚未决定什么

可以保留的知识

  • 开发者已经加入 Apple Developer Program；
  • 本机曾安装 Developer ID Application 证书及匹配私钥；
  • 签名、公证、staple 与 Gatekeeper 是四个独立结论；
  • 凭据、原始日志和本机身份信息不进入 Git。

现在不能声称

  • 公证 profile 可用（app-specific password 已停用，残留 profile 必须视为不可用）；
  • v0.8 的版本号、bundle ID、最低 macOS 或候选名已锁定；
  • 任何 keikeu 产物已经签名、公证、staple 或通过 Gatekeeper；
  • 旧工具版本和旧命令可以直接用于 v0.8。

本页不删除 Keychain 中可能残留的 profile，也不把残留项当成可用凭据。 v0.8 开始时必须重新盘点会员、证书、私钥、工具链与公证认证状态。

Route

这条路线解决什么问题

Mac App Store 外分发时，开发者需要让接收者确认软件来自已识别的 Developer ID、签名后没有被改、Apple 公证服务没有发现已知恶意内容， 并让接收者 Mac 的 Gatekeeper 按普通安全策略评估最终产物。

  1. 准备身份 会员、Developer ID 证书、匹配私钥和应用发布身份。
  2. 构建与签名 生成确定的应用与分发容器，再验证签名完整性。
  3. 公证与 staple Apple 自动检查候选并生成票据，再把票据附到产物。
  4. 接收者验证 保留 quarantine，通过普通安装与 Gatekeeper 路径验证。

Apple 官方资料同时覆盖 App Store、Xcode 原生工程、DMG、ZIP 和 PKG。 v0.8 必须先决定 keikeu 的精确分发契约，再选择对应步骤。

Beginner vocabulary

最容易混淆的词

词 准确含义 不等于
Apple Developer Program 取得 Apple 分发证书与公证服务能力的会员资格。 应用批准或发布许可。
CSR Certificate Signing Request；请求 Apple 签发证书的材料。 证书或私钥备份。
证书 把 Developer ID 身份与公钥关联起来的公开材料。 对某个应用已经完成的签名。
私钥 留在 Keychain、实际执行签名的秘密材料。 可以分享的项目文件。
.app 包含程序、资源、元数据和嵌套代码的 macOS bundle。 单个普通文件。
DMG 常见的磁盘映像分发容器。 自动完成签名或公证。
公证票据 Apple 接受公证提交后生成、与软件关联的证明。 App Review、法律背书或无漏洞保证。
Quarantine 标识外来下载来源、触发普通接收者安全路径的 macOS 属性。 应该删除的安装障碍。

Trust chain

四个动作，各管一件事

动作 它做什么 它不证明什么
Developer ID 签名 开发者用私钥声明签署来源，并使签名后的代码与资源改动可被检测。 不是发布申请，不证明 Apple 已检查或应用功能正确。
Apple 公证 Apple 自动扫描提交软件中的已知恶意内容和代码签名问题；接受后生成票据。 不是 App Review，不替代有效签名，也不保证没有未知漏洞。
Staple 把已经存在的公证票据附到对应应用、DMG 或安装包。 不重新审批、不修复签名、不重新扫描，也不决定放行。
Gatekeeper 接收者 Mac 根据来源、签名、公证证据和本机策略决定是否放行。 不执行签名、公证或 staple，也不证明产品质量。

记忆方式：签名封住字节并声明签署者；公证让 Apple 自动检查并产生 票据；staple 让产物携带票据；Gatekeeper 在接收者 Mac 上消费这些 证据。执行者、输入、输出不同，因此一步通过不能替代另外三步。

Credentials

证书与公证凭据不是一回事

Developer ID 签名身份

由证书与匹配私钥组成，用来签应用。证书可以公开验证，私钥必须留在 Keychain 或另行批准的私密存储。本 Road 不导出任何私钥或 .p12。

Notary 认证凭据

用来让 notarytool 代表开发者向 Apple 提交。当前 app-specific password 已停用，因此残留 profile 不可使用。它的 失效不等于签名证书或私钥被撤销。

v0.8 启动前不要为了练习创建新 app-specific password 或覆盖 Keychain profile。届时只有在明确批准持久修改后，才重新配置并立即验证。

密码、token、API 私钥和签名私钥不进入参数、环境变量、仓库、脚本、 聊天、截图、日志或 shell history。本机 Apple ID、Team ID 与 profile 名也不进入 Git 或证据。

Future workflow

v0.8 以后实际要验证的顺序

  1. 开发者批准 v0.8 发布契约：版本、bundle ID、架构、最低系统和容器。
  2. 盘点稳定工具链、会员、证书、匹配私钥与重新建立的公证认证。
  3. 从明确 source commit 构建应用及所有嵌套代码。
  4. 验证架构、版本、最低系统、hardened runtime 和运行时 smoke。
  5. 从同一源代码生成新的 Developer ID 签名候选。
  6. 验证嵌套签名与时间戳，建立不可变候选名和 staple 前哈希。
  7. 只提交该候选公证，审查同一次提交状态与日志。
  8. 对同一候选 staple、验证票据，并计算最终哈希。
  9. 保留 quarantine，通过普通 Gatekeeper、安装、启动和重启路径。
  10. 只分发经过验证的最终哈希；任何实质修改都生成新候选。

本页故意不提供构建、codesign、notarytool 或 DMG 命令。v0.8 工具链、 Tauri 配置和发布契约尚未锁定；复制旧命令会制造伪证据。

Evidence

安全链、运行时和产品价值要分别证明

未来可以记录

  • 版本、source commit、候选编号与工具版本；
  • 签名、公证、staple、Gatekeeper 的脱敏结论；
  • staple 前后 SHA-256；
  • 安装、启动、重启、遗漏和风险。

永远不记录

  • 私钥、密码、token、CSR 或完整签名身份；
  • 账户数据、profile 名、本机路径和原始公证日志；
  • DMG、应用 bundle 或构建输出；
  • 测试者身份、作品内容或真实 Vault 路径。

签名通过不代表公证通过；公证通过不代表 Gatekeeper 通过；安全链通过 不代表应用能保存和重启；工程通过也不代表产品达到 MVP。

Stop conditions

失败时停止，不绕过

情况 正确反应 禁止动作
证书没有匹配私钥 停止签名，核对 CSR、证书和 Keychain 归属。 导出或分享私钥来碰运气。
公证认证失败 停止提交，确认凭据是否有效；当前状态下预期不可用。 把密码贴进命令、聊天或脚本。
签名或公证失败 本机审查最小诊断，修复根因后生成新候选。 用 --deep --force 或旧票据掩盖问题。
Gatekeeper 阻止 核对最终哈希、签名、公证、quarantine 与当前策略。 右键绕过、删除 quarantine 或关闭安全策略。
怀疑凭据泄漏 停止发布、撤销相关凭据、销毁明文并重新盘点暴露面。 只移动明文文件或继续复用旧密码。

Road v0.8 restart gate

什么时候才重新开始打包

  1. 开发者明确批准 Road v0.8 的发布目标与 no-YOLO Gate；
  2. 重新锁定版本、bundle ID、架构、最低 macOS 和候选命名；
  3. 在当时的稳定 macOS、Xcode、Rust、Node、Python 与 Tauri 上盘点；
  4. 重新验证 Developer ID 证书与匹配私钥；
  5. 经明确批准生成新的公证认证，并直接保存到 Keychain；
  6. 从零实测构建、签名、公证、staple、Gatekeeper 和安装手册。

在这些条件完成前，本页只用于学习概念，不授权产生候选、修改 Keychain 或向 Apple 上传软件。
