02

一次保存怎样保护作者的内容

选择现场情况，查看页面和核心层会走哪条路。

1. 表单检查Summary 不能为空。
2. 建立 Paper模型去掉空 Highlight，整理重复 Tag。
3. 核对快照编辑页用打开时的原始字节核对文件。
4. 原子交换核心层在同目录准备临时文件，再安全替换。
5. 重建索引应用刷新可丢弃的检索元数据。

keikeu 保存新内容，然后用新快照更新编辑页。作者下次保存会基于这份快照继续核对。

编辑页负责拒绝危险保存

页面先判断 Summary。编辑已有 Paper 时，页面拒绝不存在的路径，也把打开时的字节交给核心层。核心层发现字节不一致时拒绝覆盖。

谁说了算

这套分工决定 keikeu 在崩溃、外部修改和重建时该相信什么。

Paper Markdown

作者内容的唯一主版本。每个 Paper 都是一个可读、可修的 Markdown 文件。

  • 保存 Paper、更新 Paper、分支和 Flashcard 都从它读写。
  • 索引丢失后，keikeu 扫描它重建检索数据。
  • 作者可以用文本编辑器查看它；keikeu 不会静默改写创作文本。

05

文件库负责检索、移动和可恢复的删除

Vault 允许活动区和 Trash 各保留零层或一层文件夹。文件库传递已经验证过的 Vault 相对路径。

vault/ cache/ K-20260725-001.md station/ K-20260725-002.md .trash/cache/ station/ K-20260720-001.md keikeu_index.json

检索和刷新

索引记录显示名、相对路径、文件夹、Summary、Tags 和 Highlight 名称。索引失效时，`indexer.py` 扫描 Markdown 重建它；解析问题留在 errors 中，不会把坏文件吞掉。

移动、恢复和永久删除

常规删除先移到 Trash。恢复遇到活动区同代码时会保留 Trash 项并报告冲突。永久删除只处理明确验证过的 Paper 路径。

路径防线

Vault 只能落在当前用户 Home 内。核心层拒绝 symlink 逃逸和不支持的目录结构。

vault.py · require_home_path / 路径解析
代码防线

新代码跨活动区和 Trash 分配。发现重复代码时，keikeu 报错并阻止可能覆盖资产的操作。

旧 v0.1 Vault 先在安全副本上验证，再走显式迁移和备份流程。原始不安全来源保持不动。

07

实现原则与当前状态

这些规则约束产品扩张，也让作者在文件出问题时能理解和修复。

实现原则

  • Markdown 保存作者内容，JSON 只做可重建的辅助索引。
  • UI 调用公开 Core API，不渲染 Markdown，也不直接编辑索引 JSON。
  • 保存、迁移、删除和恢复先保护已有文件，再报告失败原因。
  • keikeu 不生成、改写、评价、上传或合并作者的创作文本。
  • 系统功能在边界外处理：正文在外部编辑器，同步和冲突由 provider 负责。
