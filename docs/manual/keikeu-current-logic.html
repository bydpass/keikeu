2. Paper v4 与一次整体保存

Paper.pages[] 是内容模型

  • Paper 有可选名称、ordered Tags 和至少一张有序卡页。
  • 每页有可选标题、作者 Markdown 与可选类型。
  • Paper 本身就是可编辑、可翻页的写作锚点，不再生成另一份卡组。

Save 是唯一持久化边界

  • 加页、删页、翻页和类型切换先只改变内存草稿。
  • 保存按钮与 Cmd+S 调用同一个 whole-Paper compare-and-swap。
  • 已知失败保留 draft；未知结果只读对账，绝不自动重发。

3. Markdown、Library 与 Index v4

Paper Markdown作者内容的唯一主版本；普通文本工具可读、可修。GUI 不直接写文件。
Library按 Paper 搜索、打开、移动、分支、Trash 和恢复；搜索覆盖所有页，结果打开整份 Paper。
Index v4keikeu_index.json 是本地、可删除、可重建的辅助数据，不覆盖 Markdown 权威。
Vault作者选择 Home 内的本地目录；迁移、删除和恢复先在 fixture、synthetic Vault 或完整副本上验证。

4. 三个不能混为普通重试的状态

repair_required

文件结构无法安全解析。应用不展示半解析正文、不自动修复，转入明确的人工检查路径。

commit_unknown

写入结果无法证明。应用冻结相关 durable intent，只做 method-specific 的只读核对，不 replay mutation。

index_degraded

作者文件 mutation 已知成功，但可重建 Index 未更新。新 Paper baseline 仍成立，Index 单独处理。

dirty departure

切换 Paper、Library、Vault、新 Paper 或正常关闭前保护未保存草稿；取消后原位置和草稿不变。

5. 当前运行分层

Vue可见状态、Paper draft/baseline、活动页、导航与 pending intent；不读写 Markdown。
Tauri / Rust窗口、唯一 sidecar、串行 JSONL 队列、原生目录选择与已验证的系统动作。
JSONL protocol v2strict DTO、请求分类、locator 与一次 mutation；不是 localhost 或网络 API。
Python service / Core业务编排、校验、Paper v4 codec、Vault 文件安全、Index v4、迁移与恢复。
本地磁盘Markdown 是作者资产；Index 和设备状态是辅助数据。无账号、遥测、隐藏上传或后台同步。

6. Road v0.7 现在意味着什么

目标设计、CP0 合同与 development-only CP1 结构原型已经通过；production 仍是上面描述的 Road v0.6 runtime，CP2 才开始实现 App Shell。

  • Paper 与 Library 将成为两个同级日常位置。
  • Vault 将作为环境入口；migration、repair 和未知结果仍可接管阻塞工作面。
  • 目标窗口是 1220×780 与 920×680，并保留键盘、focus 和 reduced-motion 合同。
  • 本页、目标原型或 CP0 文档检查都不证明 CP1、production 实现、平台 smoke 或作者接受。
