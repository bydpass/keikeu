# Alpha 用户画像与宣发渠道研究

## 1. 结论先行

- 本轮没有找到能代表“18+、中文或英文、同人/OC 文字作者”的 Android、iOS、macOS、
  Windows 创作主设备占比。平台注册规模、广告设备、视频观看设备都不能替代写作设备。
- 四端占比在招募前统一记为“待 Alpha 合格报名样本实测”，不以平台大盘或全球设备份额估算。
- Road v0.8 先完成 iPhone 创作与 Mac iCloud 同步候选，再独立完成桌面对等及 Python 产品运行时退役；
  Road v0.9 才执行首轮外部 Alpha。首轮通过后再正式宣发，并进入 Android 开发与二轮 Alpha。
- 主宣发阵地为小红书和 X；Bilibili 与 YouTube 是副宣发阵地。微博和 Reddit 本轮只用于
  研究、社区观察与反证，不承担正式宣发配额。

## 2. 研究口径

本文件只使用 2026-08-30 重新检索和核对的来源，没有复制旧计划、旧调研表或旧画像数字。
“新鲜”描述的是本轮取证动作，不代表每项底层数据都发生在当天；来源日期和数据期分别列出。

目标交集是：

```text
18+ ∩ 中文或英文 ∩ 同人/OC 文字创作 ∩ 创作设备
```

证据等级：

- **高**：平台官方或监管披露，且给出日期和口径；
- **中**：平台官方产品文档，可证明能力但不能证明目标人群规模；
- **低**：第三方报告转引平台数据，无法核对稳定的一手原件。

任何证据只支持其原始分母。MAU/DAU 是平台活跃规模，观看设备是内容消费设备，广告定向设备是
触达条件；三者都不是“过去三个月完成初稿和主要修改时使用最多的设备”。

## 4. 事实、推断与建议

### 事实

- 六个平台的公开数据口径彼此不同，无法直接横向排名目标作者密度。
- YouTube 与 X 能报告或筛选内容触达设备，但这仍是消费/触达设备。
- 现有公开材料没有给出目标交集的四端创作主设备份额。

### 推断

- 小红书的可搜索 UGC 形态适合用中文图文解释“灵感 → Paper → Markdown”的工作流；这是渠道假设，
  不是作者占比结论。
- X 的公开对话、转发和搜索机制适合英文侧快速收集问题与反馈；这是运营判断，
  不是平台存在更多英文同人作者的证明。
- Bilibili 与 YouTube 更适合演示完整工作流，但视频制作成本较高，因此放在副阵地。
- 微博和 Reddit 的大盘足以支持继续观察，但本轮证据不足以证明增加正式宣发阵地会提高合格报名效率。

### 建议

- 首轮小范围公开 Alpha 招募只在小红书和 X 各发布一次，链接使用独立来源标记。
- 首轮通过后再启动正式宣发：小红书 + X 为主，Bilibili + YouTube 为辅。
- 不用设备定向广告或频道观看设备推算产品平台顺序；平台顺序由合格报名、实际任务完成和风险证据决定。
- 微博与 Reddit 只做关键词观察和反证；若后续出现持续、可复核的合格需求，再另行批准渠道实验。

## 5. Alpha 画像统计合同

### 5.1 准入与样本

合格报名必须同时满足：

- 自我声明已满 18 岁；
- 过去 12 个月进行过同人或 OC 文字创作；
- 选择中文或英文测试组，参加者只需使用其中一种语言；
- 可以使用 iPhone 或 macOS 完成首轮任务。

18+ 只用于准入，不采集生日、证件、具体年龄或年龄段，也不进入画像分析。

报名开放 14 天，目标为 60 份合格样本，中文与英文各 30。若不足 40 份，延长一次 7 天；
仍不足 40 份时只报告探索性结果，不把比例外推为总体市场。

从合格报名者中邀请 24 人，中文 12、英文 12；至少 8 人覆盖 iPhone、至少 8 人覆盖 macOS，
允许同一人覆盖两端。设备占比的分母仍是全部合格报名者，不是这 24 名入选者。

### 5.2 创作主设备

问题固定为：

> 过去三个月，你完成文字作品初稿和主要修改时使用最多的一台设备是什么？

只能单选。原始选项为 Android 手机、Android 平板、iPhone、iPad、macOS、Windows、其他。
对外四端表将 iPhone + iPad 汇总为 iOS、Android 手机 + Android 平板汇总为 Android，
同时保留 iPad 子项和 Other。Android、iOS、macOS、Windows 在报名开始前均记为：

| Android | iOS | macOS | Windows |
| --- | --- | --- | --- |
| 待 Alpha 合格报名样本实测 | 待 Alpha 合格报名样本实测 | 待 Alpha 合格报名样本实测 | 待 Alpha 合格报名样本实测 |

报告必须同时给出 `n`、原始计数、原始占比、中文/英文分组和招募来源。不得按平台 MAU 加权，
不得删去 Other 后重新归一化，也不得宣称样本代表全部同人作者。由于首轮要求参与者可使用
iPhone 或 macOS，这份四端分布天然存在准入偏差，必须随结果一起披露。

### 5.3 其他画像元素

只采集会改变产品或测试决策的字段：

- 测试语言，以及中文/英文输入法与双语切换需求；
- 过去 12 个月的创作频率、创作年限；
- 捕捉灵感、整理、初稿、主要修改、归档各阶段实际使用的设备；
- 当前工具类型与 Markdown/普通文件使用经验；
- 对本地文件、可导出性、隐私、跨设备同步的重视程度；
- 最常发生的丢灵感、找回、格式迁移或同步冲突痛点；
- 键盘、触控、字号、对比度、屏幕阅读器等输入与可访问性需求；
- 可参与的平台、测试时段和任务完成意愿。

不收平台账号、精确位置、生日、证件、私人作品名称、正文片段或真实 Vault 路径。联系方式与
研究回答分开保存，只用于 Alpha 联络；不在 App 中增加遥测。

## 6. 宣发放量 Gate

首轮 Alpha 同时满足以下条件后，才从小范围招募转为正式宣发：

- 没有未解决 P0/P1，没有静默丢稿；
- 至少 18 人完成，中文与英文各不少于 8 人；
- 创建、编辑、保存、重开、搜索、导出六项任务逐项成功率均至少 90%；分母为所有完成测试且
  被要求执行该项任务的参与者，未完成该任务计失败；
- 至少 6 人完成 iPhone ↔ macOS iCloud 往返。

Gate 通过后启动小红书 + X 主宣发、Bilibili + YouTube 副宣发，并进入 Android 开发；
Android 加入二轮 Alpha。若 Gate 未通过，先修复产品与测试流程，不用扩大曝光补偿问题。

## 7. 解释边界

本研究能决定“去哪里验证”和“怎样统计”，不能证明移动端已经实现、iCloud 已通过真机往返、
TestFlight/Developer ID 分发已经可用，或目标市场具有某个四端比例。实现与验收状态继续回到
[`PROJECT`](../../PROJECT.md) 和活动 Road 计划核对。
