# ADR-0008：完整文件夹的废纸篓生命周期

- 状态：已接受
- 日期：2026-08-25
- 决策者：开发者

## 背景

旧实现把“删除文件夹”拆成逐份 Paper 的移动，并要求目录最终为空。`.DS_Store`、嵌套目录、损坏 Markdown 或其他非 Paper 项会阻断操作，界面只能把路径交给作者手工清理。这既没有完成作者明确要求的文件夹删除，也会让目录内容处于部分移动状态。

开发者在 CP7 Gate D 整改中明确要求：文件夹删除必须处理完整目录树，不得把未知项作为人工清理阻断。

## 决策

1. 正常“删除文件夹”经一次明确确认后，把 `cache/<folder>` 这一完整顶层目录原子移动到 `.trash/cache/<folder>`。操作不解析、不重写目录内容；未知文件、嵌套目录和符号链接均随目录项移动。
2. “恢复文件夹”把同一完整目录原子移回 `cache/<folder>`。活动区存在完全同名或 NFC+casefold 等价名称时，整次恢复拒绝，不做逐项合并或部分恢复。
3. “永久删除文件夹”仅在废纸篓中经不可撤销的二次确认后执行。Core 固定精确目录身份，先以随机名称隔离，再使用不跟随符号链接的安全递归删除；平台不提供 symlink-safe `rmtree` 或目录树跨设备/包含挂载子树时，删除拒绝且恢复原名。
4. 单份 Paper 的删除、恢复和永久删除继续使用显式受验证路径与逐文件安全操作；文件夹重命名和合并继续执行严格 Paper 预检。协议方法名、DTO、Paper v4、Index v4 与 protocol v2 不变。
5. 文件夹级操作返回一条文件夹级报告。软删除与恢复失败保持全有或全无，不把未知内容路径作为正常人工清理流程。永久销毁在开始前完成身份、设备与挂载预检；递归开始后若底层删除失败，已销毁 entry 不可回滚，Core 恢复剩余目录树的原名并明确报告失败。

## 后果

- 普通删除保持可恢复，同时兑现“删除整个文件夹”的作者意图。
- 作者确认永久删除文件夹时，该目录中的未知内容也进入销毁范围；确认文案必须明确写“全部内容”。
- 符号链接本身可被删除，但永不跟随至 Vault 外部目标。
- 永久销毁经过不可撤销确认后仍可能因权限、ACL 或并发文件系统变化而部分完成；失败报告表示剩余树保留在原废纸篓名称，不能表示已销毁 entry 被恢复。
- 名称冲突不再触发隐式合并；作者必须先解决活动区或废纸篓中的目标名称。
- 本决策是 CP7 原“仅展示层”范围的窄扩展，由开发者在 Gate D 整改中明确批准；真实 Vault 操作仍需独立授权，工程验证只使用 synthetic Vault 或完整副本。

## 复审条件

若未来引入跨设备 Vault、provider mount、Windows 支持或需要可选择的合并恢复策略，必须重新设计并补充对应平台实证；不得在现有路径上静默降级为不安全递归删除。
